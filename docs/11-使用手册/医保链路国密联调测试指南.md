# 医保结算国密链路（CSSSL-SEC-V1）联调测试指南

> 适用：HIS(cslk) → 医保前置(csmig) → 医保局端(csmis) 全链路 SM2 签名 + SM4 加密双向验签。
> 状态：**2026-10-27 全链路四大场景已实测通过**（参保查询正常/篡改拦截/停保识别、2201 预结算、2301 正式结算落库扣款）。

## 1. 架构与协议

```
HIS(8080)  ──①院内段信封──►  前置 csmig(8091)  ──②局端段信封──►  医保端 csmis(8090)
           ◄──信封回执────                    ◄──信封回执────
```

- 证书链：csssl(8092) 根CA → SUB_CA → 三张服务证书（hisins/csmig/csmis），链路本地信任。
- 信封 CSSSL-SEC-V1 字段：`version`、`encData`(SM4/ECB/PKCS5Padding + base64)、`sign`(SM3withSM2 hex)、`certSerial`(叶子证书序列号 hex)、`timeStamp`(ISO-8601)、`certPem`(base64(叶子pem+SUB_CA pem))。
- 待签串：`encData|timeStamp|certSerial`；验签流：时间窗(默认300s) → 序列号一致 → leaf.verify(SUB_CA) → SUB_CA.verify(root) → SM3withSM2 → SM4 解密。
- **双段密钥隔离**：院内段（HIS↔前置）`d4ed4bcc79219747db32bd6fbcd97fe8`；局端段（前置↔医保端）`20a09e0072cce895a325a43684147195`。

## 2. 四端启动（按顺序）

| 端 | 端口 | 启动目录 | 命令 | 证书目录 |
|---|---|---|---|---|
| csssl CA | 8092 | `csssl\source\ssl_backend` | `mvn spring-boot:run` | 内置 data/certs |
| csmis 医保端 | 8090 | `csmis\source\mis_backend` | `mvn spring-boot:run` | `src\main\resources\crypto\` |
| csmig 前置 | 8091 | `csmig\source\mig_backend` | `mvn spring-boot:run` | `src\main\resources\crypto\` |
| HIS | 8080 | `cslk\source\back_end`（先 `mvn -q install -DskipTests`，再在 his-web 内 `spring-boot:run`） | | `his-web\src\main\resources\crypto\` |

配置项（均有 env 覆盖）：
- HIS：`his.insurance.crypto.enabled`(默认 true / `HIS_INS_CRYPTO_ENABLED`)、`sm4-key`(`HIS_INS_SM4_KEY`)
- csmig：`mip.crypto.enabled`、`sm4-key-his`(`MIP_SM4_KEY_HIS`)、`sm4-key-mss`(`MIP_SM4_KEY_MSS`)
- csmis：`jinb.crypto.enabled`(默认 true / `MSS_CRYPTO_ENABLED`)、`sm4-key`(`MSS_SM4_KEY`)

## 3. 联调工具与脚本（本机 Temp 目录）

- `InsCryptoTool.java`：与三端同构的协议工具。
  - 构造信封：`java -cp <classpath> InsCryptoTool build <private.pem> <certChain.pem> <sm4KeyHex> <业务JSON>`
  - 解包验签：`java -cp <classpath> InsCryptoTool unpack <root-ca.pem> <sub-ca.pem> <sm4KeyHex> <信封JSON>`
  - **业务/信封参数支持 `@文件路径` 传参**（避免 PowerShell 剥引号）；业务 JSON 含中文时**必须用文件方式**（PowerShell 内联中文会被 GBK 破坏）。
- classpath：`.;<m2>\org\bouncycastle\bcprov-jdk18on\1.78.1\bcprov-jdk18on-1.78.1.jar;<m2>\cn\hutool\hutool-all\5.8.27\hutool-all-5.8.27.jar;<m2>\com\fasterxml\jackson\core\jackson-databind\2.15.4\jackson-databind-2.15.4.jar;(jackson-core, jackson-annotations 同版本)`
- 已用脚本：`bare_call.ps1`（csmis 裸调参保查询）、`full_chain2.ps1`（HIS→前置→医保端参保查询）、`settle_2201b.ps1`/`settle_2301.ps1`（预结算/正式结算）。

### 4.1 参保查询（正常）
```
业务文件 biz-query.json = {"idCard":"430102199001011234"}
信封：InsCryptoTool build hisins-private.pem hisins-cert.pem 院内段密钥 @biz-query.json
POST http://localhost:8091/mip/insure/person/query（Content-Type: application/json，body=信封）
回执解包：InsCryptoTool unpack root-ca.pem sub-ca.pem 院内段密钥 @回执文件
期望：code=200，data.personStatus=1（430100001 在保）
```

### 4.2 篡改拦截
```
改回执/请求信封 encData 末字符后重发 → 解包回执明文 code=500,

（若改 sign/certSerial 同理被拒；时间窗超过 300s 报时间戳过期）
```

## 6. 常见问题

1. **PowerShell 直传 JSON 剥引号**：业务体/信封一律 `@文件` 传参。
2. **中文乱码导致 DTO 解析失败**：业务 JSON 必须由编辑器/Write 以 UTF-8 写盘（勿在 .ps1 内联中文再 WriteAllText，PowerShell 按 GBK 读无 BOM 脚本会破坏中文）。
3. **SM2 曲线坑**：私钥提取标量 d 后须用 `ECNamedCurveTable.getParameterSpec("sm2p256v1")` 构造，验签用 BC 底层 `SM2Signer`；勿用 JCA `Signature("SM3withSM2")`（OID 与 NIST P-256 共用导致验签恒失败）。三端代码已按此实现，勿回退。
4. **端口占用**：重启前先 `netstat -ano | findstr :8091` 找 PID 清理（避免 IDEA 调试进程与命令行进程并存）。
5. **回执解密失败 BadPadding**：确认解包用的 SM4 密钥与构造端一致（HIS/前置回 HIS 方向用院内段，前置→医保端用局端段）。
